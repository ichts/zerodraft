# WRITE_IT_DOWN static site

This directory is the independent writeitdown.app deployment, not the root Zero Draft site. Its approved phase-two brief explicitly chooses vanilla browser JavaScript and both LAMPLIGHT (dark) and DAYLIGHT (light). Do not migrate the root site's Datastar runtime or bone-only palette here.

## Map

- `index.html`: landing and directly addressable `#trial` room. The home-page H1 copy is locked to `We force you to write it down` (no final period) by captain ruling, with the captain's subheadline directly under it (`Forward only. Pause and the draft disappears. Keep going and you get to keep it.`) and the captain's three one-sentence points below the first viewport (D-040). The landing follows the captain-approved design system ("Paper in light", background A): nav brand plus a `Download for Mac` pill and the theme icon button, the H1 and its subheadline, the white demo sheet (real `demo.js` preview, at least 60% of the first viewport; no tag and no saved label on it) with the `Give it 60 seconds` room button under it (`#trial`; `room.js` returns focus to the first `#trial` link) and the one-line reassurance `No account. Nothing is saved. Just the timer.` under the button (the door and its line are measured to end above the fold at 390x844 and 1440x900, with the sans stack pinned so the host font cannot decide it), then the points band, the core rule, how it works, the facts ledger, the Mac block, the FAQ (details/summary) and a call-back band, then the footer. The JSON-LD keeps `SoftwareApplication` (macOS 14 or later, USD 4.99 `PreOrder` offer while buying is closed, download via `/download/`, no publisher or invented ratings/reviews) and `FAQPage` matching the eight visible questions and answers word for word; every fact on the page must be true of the web room and the Mac app. Faces: Newsreader for written text, Reenie Beanie only for the hand word, the system UI stack for the tool; the `#trial` room carries `.home` and uses the same tokens and components (IBM Plex Mono stays only on the legacy static pages); `qa/mac.spec.mjs` checks copy, faces, layout, the heading tree and the schema.
- `download/index.html`: the Mac free-trial download page at `/download/` (a directory because the DMG lives beside it in `download/`, uploaded separately), in the same design system as the landing. The DMG link and published SHA-256 use `data-launch` slots; `#release-notes` carries the one-line note that tells 1.0 users a newer version exists. Those three version facts flip together in the deploy that publishes a version. Release requirements are owned by `README.md` "Mac download release".)
- `site.css`: shared sheet geometry and components for the landing and room; the header `.brand` paints the plate mask on `::before` and glyph mask on `::after` so the link keeps its focus ring. See `README.md` for viewport behavior; landing colour, type, spacing, shape, depth, and motion roles are owned by `tokens.css`.
- `tokens.css`: authoritative design-system v2 tokens for the landing and room, including background option A and dark-theme overrides. Its header defines token scope, canvas-only adoption and font roles; it also owns shared writing size and placement. Only the sheet (demo and room) uses a shadow; warning and deleted state cards use the semantic wash tokens.
- `theme.js`: appearance preference only, stored under `writeitdown-theme`, the only localStorage key; labels every `[data-theme-toggle]` icon button. See `README.md` for the default and control location. The Playwright dark projects set that key.
- `demo.js`: watch-only preview replaying `demo-timeline.mjs`; also drives the landing card's draining-minute bar and silence meter. See `README.md` for the preview sequence. Never owns the actual trial.
- `demo-timeline.mjs`: deterministic seeded typing script (lines, deny beat, pacing) shared by `demo.js` and the qa specs; append-only events.
- `feedback.js`: shared deny shake and gesture-gated sound; reduced motion suppresses spatial movement.
- `session.mjs`: pure deadline adjudication and Unicode writing-unit count. Earlier deadline wins; ties wipe. See `README.md` for counting semantics.
- `room.js`: transient session owner, native textarea/IME enforcement, zen viewport, routing, clipboard. See `README.md` for writing geometry. No draft persistence or network transport.
- `privacy.html`, `terms.html`, `support.html`: honest static help/legal pages with the shared theme. Mac copy matches the 3-session trial terms on `mac.html` and `/download/`. `privacy.html#mac` states the trial session counter lives in the app settings file on the Mac and is not sent anywhere, and that the app checks for updates only when the writer turns that on in Settings or asks from the app menu (D-041).
- `what-is-write-it-down.html`, `write-it-down-mac-vs-web.html`, `write-it-down-free-trial.html`, `write-it-down-price.html`, `delete-a-draft.html`, `is-my-writing-saved.html`: answer pages using the legal-page classes. Content, discovery and schema requirements live in `README.md`, "Discovery files and answer pages".
- `mac.html`, `buy.js`: the Mac purchase page posts to the license service for a hosted checkout URL and retrieves the paid license key on return. The header uses the shared `.brand` chip-and-wordmark lockup (`../design/DESIGN.md` §11.6); the body keeps the document-style purchase layout. Purchase terms, buyer-delivery and credential-privacy requirements are owned by `README.md`, "Mac page release order". Kept out of the sitemap until LIVE sales pass the real TEST loop. Canvas-only adoption is documented in the `tokens.css` header and covered by `qa/mac.spec.mjs`.
- `session.test.mjs`: deterministic timing and multilingual-count regressions.
- `buy.test.mjs`: `node --test buy.test.mjs` executes the delivery script with DOM/HTTP/clipboard fixtures, checking exact credential bytes, empty delivery and URL cleanup without a browser.
- `qa/input-regression.js`: browser event-path checks, including synthetic IME composition; not an OS input-method test.
- `qa/zen-regression.js`: long multilingual text, fixed zen geometry, scroll containment, and deny-feedback regressions.
- `qa/seo.spec.mjs`: discovery and structured-data regressions for the contracts in `README.md`, "Discovery files and answer pages".
- `qa/mac.spec.mjs`: landing, download and Mac CTA honesty, site-wide links/fragments, release gate CLI fixtures and installer acceptance with missing file and directory guard negative controls. The header lockup, chip and responsive-header gates are specified in `../design/DESIGN.md` §11.3, §11.5 and §11.6. `qa/checkout.spec.mjs` covers hosted checkout navigation, paid key/copy, loading, neutral pending/unknown/error outcomes and credential privacy with intercepted HTTP; it does not prove a real payment.
- `qa/phase4.spec.mjs`, `playwright.config.mjs`: executable eight-project browser acceptance, accelerated clocks, screenshots, and console/network checks. Playwright is test-only; the deployed site has no package runtime.
- `og.png`: 1200×630 light-theme social share card with the wordmark-only split-W lockup, referenced by landing and download metadata.
- `logo/write-it-down-lockup.svg`, `logo/write-it-down-lockup-plate.svg`, `favicon.svg`, `favicon-16.png`, `favicon-32.png`, `favicon-dark.svg`,
  `favicon-dark-16.png`, `favicon-dark-32.png`, `apple-touch-icon.png`: the A split-W lockup and the brand favicon
  set. `../design/DESIGN.md` §11 owns the lockup composition, theme roles, favicon usage and optical sizes.
  `install.sh` owns the production file list; `qa/test-install.py` checks that the installed set matches it.
- `robots.txt`, `sitemap.xml`, `llms.txt`, and the Google/Bing verification files: crawl discovery and ownership for the apex site. Content and deployment requirements live in `README.md`, "Discovery files and answer pages".
- `journey/journey.mjs`, `journey/serve-local.mjs`: release journey gate and local artifact server, separate from `npm test`. Execution and acceptance requirements live in `README.md`, "Host routing (Caddy) and the release journey gate".
- `journey/waivers.json`: authoritative sign-in exemption and integration-only delivery approval with installed-DMG TEST acceptance pending for the maintainer. `journey/waivers.mjs` enforces approval, sign-in absence and the LIVE-sales block; `journey/waivers.test.mjs` covers validation. The `mac-purchase` journey intercepts all checkout/license calls and the hosted destination, asserting integration only. See `README.md` for the release procedure.
- `journey/verify-room.mjs`: room negative-control runner. Procedure and evidence requirements live in `README.md`.
- `install.sh`: fixed-target, backed-up deployment inside `/var/www/writeitdown.app/` only. Creates `download/` and `logo/` and installs only `download/index.html` from here; the DMG and the Sparkle feed (`download/appcast.xml` plus `download/updates/` payloads) are placed separately and are never part of the site bundle, so an install can neither overwrite nor prune them. Refuses a symlink target, file, or destination directory before writing. Installs `buy.js`; no waitlist-collector dependency. Service readiness and TEST-to-LIVE acceptance are separate gates in `README.md`.
- `QA.md`: browser acceptance and remaining limits.

The landing and room share the approved Paper in light design through `tokens.css` and `site.css`. Do not ship `.dc.html` preview scaffolding, frameworks, or design-board runtime. The only analytics is the cookieless Cloudflare Web Analytics beacon, once before `</body>` on ordinary pages. `mac.html?session_id=...` suppresses it to avoid leaking a buyer credential.

Validate with `node --test writeitdown/session.test.mjs` and `cd writeitdown && npm ci && npx playwright test` (installed Chrome required). The browser suite serves HTTP and covers both themes at 1440x900 and 390x844, normal and reduced motion, with accelerated clocks. The room starts on first input, not entry. Kept text is visible only until exit/reload. Never store or submit writing. The public contact is contact@trefoilstudio.com; do not add other addresses without confirmation.
