# WRITE_IT_DOWN static site

This directory is the independent writeitdown.app deployment, not the root Zero Draft site. Its approved phase-two brief explicitly chooses vanilla browser JavaScript and both LAMPLIGHT (dark) and DAYLIGHT (light). Do not migrate the root site's Datastar runtime or bone-only palette here.

## Map

- `index.html`: landing and directly addressable `#trial` room. The home-page H1 copy is locked to `We force you to write it down` (no final period) by captain ruling, with the captain's subheadline directly under it (`Forward only. Pause and the draft disappears. Keep going and you get to keep it.`). The landing follows the captain-approved design system ("Paper in light", background A): nav brand plus a `Download for Mac` pill and the theme icon button, the H1 and its subheadline, the `Give it 60 seconds` door (`#trial`; `room.js` returns focus to the first `#trial` link), then the white demo sheet (real `demo.js` preview, at least 60% of the first viewport and 60% of it on the first screen; no tag and no saved label on it), then the core rule, how it works, the Mac card (a heading, the two actions and the four price/trial/refund facts), and the FAQ (details/summary), then the footer. The door is the page's only entrance and sits above the demo in one vertical rhythm read from the page's spacing tokens (D-047); the reassurance line, the points band, the facts table, the Mac paragraph and its requirements line, and the closing block were removed as content that describes or restates rather than states a fact. Copy follows Q-20 in `../docs/ui-quality.md`: a mechanism, a number, a price or a requirement, never an introduction to itself. The JSON-LD keeps `SoftwareApplication` (macOS 14 or later, USD 4.99 `PreOrder` offer while buying is closed, download via `/download/`, no publisher or invented ratings/reviews) and `FAQPage` matching the eight visible questions and answers word for word; every fact on the page must be true of the web room and the Mac app. Faces: Newsreader for written text, Reenie Beanie only for the hand word, the system UI stack for the tool; the `#trial` room carries `.home` and uses the same tokens and components (IBM Plex Mono stays only on the legacy static pages); `qa/mac.spec.mjs` checks copy, faces, layout, the heading tree and the schema.
- `download/index.html`: the Mac free-trial download page at `/download/` (a directory because the DMG lives beside it in `download/`, uploaded separately), in the same design system as the landing. The DMG link and published SHA-256 use `data-launch` slots; the Install card's `shasum` command names the same DMG; `#release-notes` always declares the linked DMG's version in `data-release-note` and stays empty and hidden until there is a newer release to announce. The download card states no badge: the requirements list already carries the trial, price and refund facts. Those four version facts (DMG link name, Install command filename, SHA-256, release note) flip together in the deploy that publishes a version, and `release-check.mjs` refuses an Install command that names a different DMG than the link. Release requirements are owned by `README.md` "Mac download release".- `site.css`: shared shell and components for every shipped page; the header `.brand` paints the plate mask on `::before` and glyph mask on `::after` so the link keeps its focus ring. The landing and room components sit beside one document shell (`main.doc`: 62ch measure, 17 px system face, Newsreader headings, `.qa` answer blocks, `.home-foot`) used by the nine help/legal/answer pages and `mac.html`, plus the purchase components (`.doc-buy`, `.price-row`, `.license-card`). There is no second reading mode. See `README.md` for viewport behavior; colour, type, spacing, shape, depth, and motion roles are owned by `tokens.css`.
- `tokens.css`: authoritative design-system v2 tokens for every shipped page (landing, download, room, the help/legal/answer pages and `mac.html`), including background option A and dark-theme overrides. Its header defines token scope and font roles; every page takes the full role set by putting `.home` on `<body>` or its main surface, with the canvas through `.page-a`. It also owns shared writing size and placement. Only the sheet (demo and room) uses a shadow; warning and deleted state cards use the semantic wash tokens.
- `theme.js`: appearance preference only, stored under `writeitdown-theme`, the only localStorage key; labels every `[data-theme-toggle]` icon button. See `README.md` for the default and control location. The Playwright dark projects set that key.
- `demo.js`: watch-only preview replaying `demo-timeline.mjs`; renders the same room the trial and the Mac show (35% anchor, stepped history, ink-placed warning group, status-slot receipt, the `You stopped.` failure stage without controls, one continuous 2 pt bar) driven by an absolute-deadline linear bar, re-anchored after hidden intervals or motion-preference changes. Completed lines join the existing history stack and shift by one pitch using the room's shared timing and easing. See `README.md` for the preview sequence. Never owns the actual trial.
- `demo-timeline.mjs`: deterministic seeded typing script (lines, deny beat, pacing) shared by `demo.js` and the qa specs; append-only events.
- `feedback.js`: shared one-pitch shift timing/easing and the shared refusal, `denyFeedback(paper, hairline)`: a 200 ms transform-only shake and a 220 ms opacity-only red hairline flash, restartable on a repeat; Reduce Motion keeps only the flash. It is visual and live-region only, never audible (D-046).
- `status-slot.js`: the one ink placement for the warning numeral, caption and wipe receipt shared by `room.js` and `demo.js` (numeral ink 44 px under the writing baseline, caption ink 20 px under the numeral's ink, receipt in the numeral's slot). When the warning group cannot fit above the footer it moves above the active line, the failure block and receipt clamp above the footer, and the kept screen derives its top/bottom and compact title spacing from the same paper height; a tall sheet keeps the Mac offsets and the kept screen reserves the measured exit confirmation row at every width (inline top on desktop, wrapped row on phones), so arming it neither reflows nor overlaps a result screen. The kept screen also guarantees the returned draft at least one rendered line: it measures the draft's line box against the scroll box and, only when the block above it squeezes that line, shrinks its own gaps (draft, then actions, then receipt) until a line fits, so no font metric can clip the kept draft. Cached on the three strings; callers invalidate on resize, font load, route or visibility change.
- `session.mjs`: pure deadline adjudication and Unicode writing-unit count. Earlier deadline wins; ties wipe. See `README.md` for counting semantics.
- `room.js`: transient session owner, native textarea/IME enforcement, zen viewport, routing, clipboard. The room matches the shipped Mac room (D-043): 35% anchor, `Type to start` count prompt and `0 words` after a wipe, stepped per-line mask with a one-pitch 180 ms shift, ink-placed warning group and status-slot receipt, one linear 2 pt session bar, `You stopped.` / `Begin again` failure screen, fixed kept top block, two-step exit with an inline confirmation. See `README.md` for writing geometry. No draft persistence or network transport.
- `privacy.html`, `terms.html`, `support.html`: honest static help/legal pages on the shared document shell: the landing header with its plate and theme button, 62ch body copy in the system face, the landing footer, and no IBM Plex Mono. Mac copy matches the 3-session trial terms on `mac.html` and `/download/`. `privacy.html#mac` states the trial session counter lives in the app settings file on the Mac and is not sent anywhere, and that the app checks for updates only when the writer turns that on in Settings or asks from the app menu (D-041).- `what-is-write-it-down.html`, `write-it-down-mac-vs-web.html`, `write-it-down-free-trial.html`, `write-it-down-price.html`, `delete-a-draft.html`, `is-my-writing-saved.html`: answer pages on the same document shell, with a breadcrumb, one H1, body copy and `.qa` question/answer blocks (the serif question sits above the sans answer). Content, discovery and schema requirements live in `README.md`, "Discovery files and answer pages".
- `mac.html`, `buy.js`: the Mac purchase page is the shared document shell, not a second design system: the same header lockup, footer, 17 px body and v2 pill buttons as every other page, with a `#buy` section (heading, `$4.99 once` price row, form) that carries `scroll-margin` so the anchor lands in view, and a `.license-card` for the pending, ready, copied and unpaid states. It posts to the license service for a hosted checkout URL and retrieves the paid license key on return; `buy.js` removes the `session_id` credential from the address bar and history when the license response arrives, on success and failure, and offers `Check again` from page memory. Purchase terms, buyer-delivery and credential-privacy requirements are owned by `README.md`, "Mac page release order". Kept out of the sitemap until LIVE sales pass the real TEST loop. The shell and the buy-path assertions are covered by `qa/shell.spec.mjs`, `qa/mac.spec.mjs` and `qa/checkout.spec.mjs`.
- `release-check.mjs`: `npm run release-check` (add `-- --live` to fetch the URLs), the pre-publish gate. `-- --download` checks only the download page: a real https `.dmg` link, a 64-hex SHA-256, an Install card whose `shasum` command names that same DMG, a DMG file name that carries its version as `Write-It-Down-<version>.dmg`, and a release note that declares the linked DMG's version; with `--live` it also fetches the served DMG and checks its hash. The Sparkle feed is not covered yet; a bounded follow-up adds `--appcast` (feed version vs page, enclosure length vs hosted archive). The default also requires live checkout and license slots and fails on missing or placeholder launch inputs, a missing support address, or a mismatch with the app's `Info.plist` price and checkout URL. A pass is not proof of a working sale; opening still needs a real test order and an explicit go. `--live-sales` rejects a LIVE claim while `journey/waivers.json` records pending installed-DMG TEST acceptance. Not shipped.
- `session.test.mjs`: deterministic timing and multilingual-count regressions.
- `buy.test.mjs`: `node --test buy.test.mjs` executes the delivery script with DOM/HTTP/clipboard fixtures, checking exact credential bytes, empty delivery and URL cleanup without a browser.
- `qa/input-regression.js`: browser event-path checks, including synthetic IME composition; not an OS input-method test.
- `qa/zen-regression.js`: long multilingual text, fixed zen geometry, the stepped per-line mask, scroll containment, and the 200 ms/220 ms refusal regression.
- `qa/seo.spec.mjs`: discovery and structured-data regressions for the contracts in `README.md`, "Discovery files and answer pages".
- `qa/shell.spec.mjs`: the site-wide shell contract, measured rather than eyeballed: brand y, theme plate, body family and canvas identical across the twelve shipped pages; 17 px sans copy at the 62ch measure; link contrast at or above 4.5:1; `#buy` landing with its heading and price row in view; one price string; the phone room nav with only the theme icon and the Mac link in the exit row; and a missing page answering 404 through the release route server (`journey/serve-local.mjs`).
- `qa/mac.spec.mjs`: landing, download and Mac CTA honesty, site-wide links/fragments, release gate CLI fixtures and installer acceptance with missing file and directory guard negative controls. The header lockup, chip and responsive-header gates are specified in `../design/DESIGN.md` §11.3, §11.5 and §11.6. `qa/checkout.spec.mjs` covers hosted checkout navigation, paid key/copy, loading, neutral pending/unknown/error outcomes and credential privacy with intercepted HTTP; it does not prove a real payment.
- `qa/motion-regression.spec.mjs`: demo history continuity, deadline-aligned bar re-anchoring after hidden loops and motion-setting changes, and repeated refusal presentation continuity on both surfaces.
- `qa/phase4.spec.mjs`, `playwright.config.mjs`: executable eight-project browser acceptance, accelerated clocks, screenshots, and console/network checks. It carries the web half of the Mac parity contract (anchor, count prompt, history ladder, ink-placed warning and receipt, one bar, failure and kept screens, two-step exit, refusal timings), measured rather than eyeballed. Playwright is test-only; the deployed site has no package runtime.
- `og.png`: 1200×630 light-theme social share card with the wordmark-only split-W lockup, referenced by landing and download metadata.
- `logo/write-it-down-lockup.svg`, `logo/write-it-down-lockup-plate.svg`, `favicon.svg`, `favicon-16.png`, `favicon-32.png`, `favicon-dark.svg`,

  `install.sh` owns the production file list; `qa/test-install.py` checks that the installed set matches it.
- `robots.txt`, `sitemap.xml`, `llms.txt`, and the Google/Bing verification files: crawl discovery and ownership for the apex site. Content and deployment requirements live in `README.md`, "Discovery files and answer pages".
- `journey/journey.mjs`, `journey/serve-local.mjs`: release journey gate and local artifact server, separate from `npm test`. Execution and acceptance requirements live in `README.md`, "Host routing (Caddy) and the release journey gate".
- `journey/waivers.json`: authoritative sign-in exemption and integration-only delivery approval with installed-DMG TEST acceptance pending for the maintainer. `journey/waivers.mjs` enforces approval, sign-in absence and the LIVE-sales block; `journey/waivers.test.mjs` covers validation. The `mac-purchase` journey intercepts all checkout/license calls and the hosted destination, asserting integration only. See `README.md` for the release procedure.
- `journey/verify-room.mjs`: room negative-control runner. Procedure and evidence requirements live in `README.md`.
- `install.sh`: fixed-target, backed-up deployment inside `/var/www/writeitdown.app/` only. Creates `download/` and `logo/` and installs only `download/index.html` from here; the DMG and the Sparkle feed (`download/appcast.xml` plus `download/updates/` payloads) are placed separately and are never part of the site bundle, so an install can neither overwrite nor prune them. Refuses a symlink target, file, or destination directory before writing. Installs `buy.js`; no waitlist-collector dependency. Service readiness and TEST-to-LIVE acceptance are separate gates in `README.md`.
- `QA.md`: browser acceptance and remaining limits.

Every shipped page shares the approved Paper in light design through `tokens.css` and `site.css`. Do not ship `.dc.html` preview scaffolding, frameworks, or design-board runtime. The only analytics is the cookieless Cloudflare Web Analytics beacon, once before `</body>` on ordinary pages. `mac.html?session_id=...` suppresses it to avoid leaking a buyer credential.

Validate with `node --test writeitdown/session.test.mjs` and `cd writeitdown && npm ci && npx playwright test` (installed Chrome required). The browser suite serves HTTP and covers both themes at 1440x900 and 390x844, normal and reduced motion, with accelerated clocks. The room starts on first input, not entry. Kept text is visible only until exit/reload. Never store or submit writing. The public contact is contact@trefoilstudio.com; do not add other addresses without confirmation.
