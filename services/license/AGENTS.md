# License service module

`README.md` owns the HTTP, Mac token and operational contract. `service.go` owns provisional business-event processing, SQLite licenses and activations, and offline Ed25519 tokens; `waffo.go` owns documented t/v1 callback authentication and SDK replay freshness; `migrations.go` upgrades local callback receipts for replay-conflict checks. `stripe.go` owns the environment-paired Stripe HMAC adapter, Checkout API, buyer credential retrieval, session/payment-intent binding and SQLite event receipts. TEST/LIVE keep one stable app product, signing key and token format; the configured price is the billing boundary. `http.go` owns bounded request admission, proxy-address trust, database-free health, exact buyer-origin CORS and provider-selected checkout routing; Waffo checkout still fails closed. `capture.go` owns opt-in bounded, atomic private callback evidence, oldest-record eviction and expiry cleanup. Capture is best-effort before verification: failures never bypass or block authorization. `main.go` owns provider/mode configuration, key-file checks, capture configuration, loopback binding and shutdown. `admin.go` owns offline manual revocation. Default tests cover synthetic signed events and a real local HTTP listener. The explicit `wafforeal` suite uses private external captures plus a committed hash manifest; it proves transport signatures, not business mapping or a completed provider integration. `deploy/README.md`, `deploy/DEPLOY.md` and the templates prepare the maintainer's permanent replacement, TEST-first acceptance, environment switch and rollback; they do not deploy anything. Backup configuration follows the selected `LICENSE_DB`.

`README.md` owns merchant configuration, capture handling and the unverified provider contract. Treat private captures as restricted evidence, never logs or public fixtures; do not infer provider behavior from local tests. This module never contacts Waffo or stores application drafts. Stripe mode contacts its configured API with a matching TEST/LIVE key; genuine TEST payment, buyer receipt-page integration and Mac activation still need independent acceptance. The host's existing token key is authoritative: never replace or ship it in a bundle. Worker validation uses only local synthetic keys and never contacts LIVE. Keep private keys and order credentials out of logs, committed fixtures and source. Run `go test ./... && go vet ./... && go build .` here, with `go test -race ./...` for request/storage changes. Follow the README's test-order gates before enabling payments.
