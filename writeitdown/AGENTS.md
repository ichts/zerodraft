# WRITE_IT_DOWN static site

This directory is the independent writeitdown.app deployment, not the root Zero Draft site. Its approved phase-two brief explicitly chooses vanilla browser JavaScript and both LAMPLIGHT (dark) and DAYLIGHT (light). Do not migrate the root site's Datastar runtime or bone-only palette here.

## Map

- `index.html`: landing and directly addressable `#trial` room. The home-page H1 copy is locked to `We force you to write it down` (no final period) by captain ruling. The landing follows the captain-approved design system ("Paper in light", background A): nav brand plus a `Download for Mac` pill and the theme icon button, the H1, the white demo sheet (real `demo.js` preview, at least 60% of the first viewport; no tag and no saved label on it) with only the `Give it 60 seconds` room button under it (`#trial`; `room.js` returns focus to the first `#trial` link), then the core rule, how it works, the facts ledger, the Mac block, the FAQ (details/summary) and a call-back band, then the footer. The JSON-LD keeps `SoftwareApplication` (macOS 14 or later, USD 4.99 `PreOrder` offer while buying is closed, download via `/download/`, no publisher or invented ratings/reviews) and `FAQPage` matching the eight visible questions and answers word for word; every fact on the page must be true of the web room and the Mac app. Faces: Newsreader for written text, Reenie Beanie only for the hand word, the system UI stack for the tool; the `#trial` room carries `.home` and uses the same tokens and components (IBM Plex Mono stays only on the legacy static pages); `qa/mac.spec.mjs` checks copy, faces, layout, the heading tree and the schema.
- `download/index.html`: the Mac free-trial download page at `/download/` (a directory because the DMG lives beside it in `download/`, uploaded separately), in the same design system as the landing. The DMG link and published SHA-256 use `data-launch` slots. Release requirements are owned by `README.md` "Mac download release".
- `site.css`: shared sheet geometry and components for the landing and room; the header `.brand` is the lockup mask described above. See `README.md` for viewport behavior; landing colour, type, spacing, shape, depth, and motion roles are owned by `tokens.css`.
- `tokens.css`: authoritative design-system v2 tokens for the landing and room, including background option A and dark-theme overrides. Its header defines token scope, canvas-only adoption and font roles; it also owns shared writing size and placement. Only the sheet (demo and room) uses a shadow; warning and deleted state cards use the semantic wash tokens.
- `theme.js`: appearance preference only, stored under `writeitdown-theme`, the only localStorage key; labels every `[data-theme-toggle]` icon button. See `README.md` for the default and control location. The Playwright dark projects set that key.
- `demo.js`: watch-only preview replaying `demo-timeline.mjs`; also drives the landing card's draining-minute bar and silence meter. See `README.md` for the preview sequence. Never owns the actual trial.
- `demo-timeline.mjs`: deterministic seeded typing script (lines, deny beat, pacing) shared by `demo.js` and the qa specs; append-only events.
- `feedback.js`: shared deny shake and gesture-gated sound; reduced motion suppresses spatial movement.
- `session.mjs`: pure deadline adjudication and Unicode writing-unit count. Earlier deadline wins; ties wipe. See `README.md` for counting semantics.
- `room.js`: transient session owner, native textarea/IME enforcement, zen viewport, routing, clipboard. See `README.md` for writing geometry. No draft persistence or network transport.
- `privacy.html`, `terms.html`, `support.html`: honest static help/legal pages with the shared theme. Mac copy matches the 3-session trial terms on `mac.html` and `/download/`. `privacy.html#mac` states the trial session counter lives in the app settings file on the Mac and is not sent anywhere.
- `what-is-write-it-down.html`, `write-it-down-mac-vs-web.html`, `write-it-down-free-trial.html`, `write-it-down-price.html`, `delete-a-draft.html`, `is-my-writing-saved.html`: answer pages using the legal-page classes. Content, discovery and schema requirements live in `README.md`, "Discovery files and answer pages".
- `mac.html`, `buy.js`: the Mac purchase page posts to the license service for a hosted checkout URL and retrieves the paid license key on return. Purchase terms, buyer-delivery and credential-privacy requirements are owned by `README.md`, "Mac page release order". Kept out of the sitemap until LIVE sales pass the real TEST loop. Canvas-only adoption is documented in the `tokens.css` header and covered by `qa/mac.spec.mjs`.
- `release-check.mjs`: `npm run release-check` (add `-- --live` to fetch the URLs), the pre-publish gate. `-- --download` checks only the download page: a real https `.dmg` link and a 64-hex SHA-256, and with `--live` that the served DMG hashes to it. The default also requires live checkout and license slots and fails on missing or placeholder launch inputs, a missing support address, or a mismatch with the app's `Info.plist` price and checkout URL. A pass is not proof of a working sale; opening still needs a real test order and an explicit go. `--live-sales` rejects a LIVE claim while `journey/waivers.json` records pending installed-DMG TEST acceptance. Not shipped.
- `session.test.mjs`: deterministic timing and multilingual-count regressions.
- `qa/input-regression.js`: browser event-path checks, including synthetic IME composition; not an OS input-method test.
- `qa/zen-regression.js`: long multilingual text, fixed zen geometry, scroll containment, and deny-feedback regressions.
- `qa/seo.spec.mjs`: discovery and structured-data regressions for the contracts in `README.md`, "Discovery files and answer pages".
- `qa/mac.spec.mjs`: landing, download and Mac CTA honesty, site-wide links/fragments, release gate CLI fixtures and installer acceptance with a missing-guard negative control. `qa/checkout.spec.mjs` covers hosted checkout navigation, paid key/copy, loading, neutral pending/unknown/error outcomes and credential privacy with intercepted HTTP; it does not prove a real payment.
- `qa/phase4.spec.mjs`, `playwright.config.mjs`: executable eight-project browser acceptance, accelerated clocks, screenshots, and console/network checks. Playwright is test-only; the deployed site has no package runtime.
- `og.png`: 1200×630 light-theme social share card referenced by landing metadata.
- `logo/write-it-down-lockup.svg`, `favicon.svg`, `favicon-16.png`, `favicon-32.png`, `favicon-dark.svg`,
  `favicon-dark-16.png`, `favicon-dark-32.png`, `apple-touch-icon.png`: the A split-W lockup and the brand favicon
  set. `site.css` draws the wordmark as a `currentColor` mask from the lockup SVG, so one vector serves light and
  dark; the default favicon is the full-bleed bone square with the ink W, and the dark `prefers-color-scheme` links
  use the ink square with the bone W. The usage rules and optical sizes are owned by `../design/DESIGN.md` §11.
  `install.sh` and `qa/test-install.py` list the eight files exactly, so a deploy and the installer acceptance
  cannot drift.
- `robots.txt`, `sitemap.xml`, `llms.txt`, and the Google/Bing verification files: crawl discovery and ownership for the apex site. Content and deployment requirements live in `README.md`, "Discovery files and answer pages".
- `journey/journey.mjs`, `journey/serve-local.mjs`: release journey gate and local artifact server, separate from `npm test`. Execution and acceptance requirements live in `README.md`, "Host routing (Caddy) and the release journey gate".
- `journey/waivers.json`: authoritative sign-in exemption and integration-only delivery approval with installed-DMG TEST acceptance pending for the maintainer. `journey/waivers.mjs` enforces approval, sign-in absence and the LIVE-sales block; `journey/waivers.test.mjs` covers validation. The `mac-purchase` journey intercepts all checkout/license calls and the hosted destination, asserting integration only. See `README.md` for the release procedure.
- `journey/verify-room.mjs`: room negative-control runner. Procedure and evidence requirements live in `README.md`.
- `install.sh`: fixed-target, backed-up deployment inside `/var/www/writeitdown.app/` only. Creates `download/` and installs only its `index.html`; the DMG is placed there separately. Installs `buy.js`; no waitlist-collector dependency. Service readiness and TEST-to-LIVE acceptance are separate gates in `README.md`.
- `QA.md`: browser acceptance and remaining limits.

The landing and room share the approved Paper in light design through `tokens.css` and `site.css`. Do not ship `.dc.html` preview scaffolding, frameworks, or design-board runtime. The only analytics is the cookieless Cloudflare Web Analytics beacon, once before `</body>` on ordinary pages. `mac.html?session_id=...` suppresses it to avoid leaking a buyer credential.

Validate with `node --test writeitdown/session.test.mjs` and `cd writeitdown && npm ci && npx playwright test` (installed Chrome required). The browser suite serves HTTP and covers both themes at 1440x900 and 390x844, normal and reduced motion, with accelerated clocks. The room starts on first input, not entry. Kept text is visible only until exit/reload. Never store or submit writing. The public contact is contact@trefoilstudio.com; do not add other addresses without confirmation.
